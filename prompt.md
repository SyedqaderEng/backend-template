API-first backend and a complementary frontend using a prompt-driven approach.

25 Prompts for Backend API Services

This sequence will establish the core infrastructure, security, data models, external service integrations (Clerk, Supabase, Stripe, etc.), and necessary documentation (Swagger/OpenAPI, GraphQL).

Phase 1: Infrastructure, Security & Base API (Prompts 1-5)

Prompt #	Task Title	Detailed Tasks (4-5 per prompt)
P-B-1	Project Setup and Core Dependency Definition	1. Define the project structure using Node.js/TypeScript (or preferred language). 2. Install core dependencies (framework like Express/Fastify, logging, validation). 3. Create initial environment variables structure (e.g., CLERK_SECRET_KEY, SUPABASE_URL). 4. Establish a basic API Route file (e.g., /api/health) for server verification.
P-B-2	Secure Environment and CORS Configuration	1. Implement secure environment variable loading/management. 2. Configure CORS (Cross-Origin Resource Sharing) to accept requests only from the specified frontend domain(s). 3. Define and secure all configuration files outside the publicly accessible project structure. 4. Implement a standardized logging system for request tracing and error capture.
P-B-3	Clerk Authentication Middleware Integration	1. Integrate the Clerk SDK for backend use. 2. Create a global Authentication Middleware function. 3. This middleware must verify the incoming JWT from the frontend request header. 4. If valid, attach the user object (ID, roles) to the request; if invalid, return a 401 Unauthorized response.
P-B-4	Supabase Client and Connection Setup	1. Install the Supabase SDK for server-side use. 2. Configure the connection using the secure Service Role Key (for privileged operations). 3. Implement a reusable database client wrapper function for consistent connection handling. 4. Define the initial basic Supabase database schema (e.g., profiles table).
P-B-5	Initial User Profile API Endpoints	1. Create the API endpoint GET /api/v1/users/me using the auth middleware. 2. Implement logic to fetch the user's data from the Supabase profiles table using the authenticated user ID. 3. Create the API endpoint PATCH /api/v1/users/me to allow authenticated users to update their profile (e.g., name). 4. Ensure Row-Level Security (RLS) is respected for any sensitive data.

Phase 2: External Services Integration (Prompts 6-12)

Prompt #	Task Title	Detailed Tasks (4-5 per prompt)
P-B-6	Stripe Configuration and Product Setup	1. Install the Stripe SDK. 2. Configure the Stripe client using the secure Stripe Secret Key. 3. Define environment variables for all Stripe Product IDs (Basic, Pro, etc.). 4. Implement a server-side helper function to safely retrieve subscription plan data from Stripe.
P-B-7	Secure Stripe Checkout Session API	1. Create the API endpoint POST /api/v1/subscriptions/checkout-session. 2. This endpoint must take the desired plan_id from the frontend. 3. Use the Stripe SDK to securely create a Checkout Session URL. 4. Pass the authenticated user's Clerk ID as metadata to Stripe. 5. Return the secure session URL to the frontend.
P-B-8	Stripe Webhook Handler Endpoint (Critical)	1. Create a public, unauthenticated API endpoint POST /api/webhooks/stripe. 2. Implement the logic to verify the Stripe signature header using the Webhook Secret. 3. Write handlers for critical events (checkout.session.completed, customer.subscription.updated). 4. Upon a successful event, update the corresponding user's subscription status in the Supabase Database.
P-B-9	Subscription Status Management API	1. Create the API endpoint GET /api/v1/subscriptions/current-plan. 2. Use the authenticated user ID to fetch their current subscription status from the Supabase database. 3. Implement logic to check the subscription expiration and status (active, cancelled, past_due). 4. Return the consolidated plan data to the frontend for dashboard display.
P-B-10	Secure Billing Portal API (Cancellation/Upgrade)	1. Create the API endpoint POST /api/v1/billing/portal. 2. Use the Stripe SDK to securely generate a Billing Portal Session URL for the authenticated user. 3. This allows the user to manage their subscription/invoices directly on Stripe without exposing API secrets. 4. Return the secure portal URL to the frontend.
P-B-11	Resend (Email) Integration and Helper	1. Install the Resend SDK. 2. Configure the client using the secure Resend API Key. 3. Create a server-side helper function (e.g., sendWelcomeEmail(user)) for sending transactional emails. 4. Integrate this helper into the Stripe Webhook Handler (P-B-8) to send a "Subscription Active" email.
P-B-12	UploadThing Integration and Presigned URL	1. Integrate the UploadThing SDK. 2. Create the API endpoint POST /api/v1/upload/file-url. 3. This endpoint generates a presigned URL that the frontend can use to securely upload files directly to the storage service (e.g., S3). 4. Ensure the URL is associated with the authenticated user ID for later permission checks.

Phase 3: Documentation and Advanced Features (Prompts 13-17)

Prompt #	Task Title	Detailed Tasks (4-5 per prompt)
P-B-13	OpenAPI/Swagger Documentation Setup	1. Integrate a Swagger/OpenAPI documentation tool (e.g., Swagger UI, Redoc). 2. Define the base API schema (title, version, server URL). 3. Add documentation metadata for the Authentication Middleware (P-B-3). 4. Configure the documentation to be accessible via a dedicated route (e.g., /api-docs).
P-B-14	Documenting Core REST Endpoints	1. Write the full OpenAPI specification for /api/v1/users/me (P-B-5), including request body and 200/401/500 responses. 2. Document the structure and parameters for the POST /api/v1/subscriptions/checkout-session endpoint (P-B-7). 3. Ensure all data models (schemas) are defined clearly within the specification. 4. Generate and verify the live Swagger documentation.
P-B-15	GraphQL Schema Definition and Server Setup	1. Install necessary GraphQL dependencies (e.g., Apollo Server, GraphQL.js). 2. Define the root GraphQL Schema containing core types (User, Subscription, Plan). 3. Set up the GraphQL server endpoint (e.g., /graphql). 4. Implement GraphQL resolvers for fetching the authenticated user's profile (me).
P-B-16	GraphQL Resolver for Subscription Data	1. Create a GraphQL query resolver named currentSubscription for the Subscription type. 2. Implement the resolver logic to fetch consolidated subscription data using the secure server-side logic (similar to P-B-9). 3. Ensure the resolver integrates the Authentication Middleware (P-B-3) for authorization. 4. Test the query using the GraphQL Playground/GraphiQL interface.
P-B-17	Input Validation and Error Handling Standardization	1. Implement a robust input validation library (e.g., Zod, Joi) for all POST/PATCH requests. 2. Standardize error response format (e.g., { "status": 400, "message": "Invalid input" }). 3. Implement a global error handler to catch uncaught exceptions and return standardized 500 responses. 4. Apply input validation to the profile update (P-B-5) and checkout session (P-B-7) endpoints.
